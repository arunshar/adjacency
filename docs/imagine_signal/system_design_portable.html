1. What the system does

An advertiser has one approved ad image. The obvious move is to generate fifty more. You then have fifty images and no idea which difference mattered, what it cost, or whether you are allowed to say anything about it.

ImagineSignal builds a small family in which exactly one declared visual choice changes at a time, with product, logo, composition and text locked and verified byte-identical. It records lineage and actual cost, joins clearly labeled outcome evidence, and passes every conclusion through nine deterministic gates before recommending anything.

The output is not an image. It is a decision receipt: keep, edit, test, hold, review, or stop, with the evidence class that justified it attached.

The design claim. The interesting engineering is not generation. It is that the system refuses to claim more than its evidence supports, and the refusal is enforced by types and pure functions rather than by a style guide.

2. High-level design

Base Adjacency (gates G0 to G6) is untouched. ImagineSignal is isolated under src/adjacency/imagine_signal/ with gates IS0 to IS8 and its own canonical hashing, so its contracts can evolve without moving existing hash vectors.

3. Component design

Asymmetric coverage, on purpose. The pure core is held at 100 percent line and branch in CI. The I/O layers sit against a 55 percent floor. A bad verdict from a badly written I/O layer still gets caught by the gates, so exhaustive branch coverage there buys much less. The gates are the safety net, so the gates are what gets tested exhaustively.

4. The transport seam and the cost interlock

The entire provider integration is one Protocol with one method:

class ImagineTransport(Protocol):
    def invoke(self, *, operation, request) -> TransportResult: ...
PropertyWhy it is built that way
Replay is the defaultNo credential, no socket. The business logic is testable without a network or a bill.
A missing fixture is terminalA fallback from replay to a live call is how you get a surprise bill and an unreproducible result.
One invocation per callRetries hide provider state and multiply spend exactly when you can least reason about it.
Unknown cost blocks spendingZero is a reported value, never a default. This is what makes it safe to leave running unattended.

5. The gate chain and the evidence ceiling

Evidence classActions admitted
PROPOSED IMPLEMENTED UNIT_TESTEDHOLD, REVIEW, STOP
FROZEN_REPLAY SIMULATED and aboveKEEP, EDIT, TEST, HOLD, REVIEW, STOP

Restrictiveness ordering is total: TEST(0) < EDIT(1) < KEEP(2) < HOLD(3) < REVIEW(4) < STOP(5). One failed gate can only make the outcome stricter, never looser.

What this forecloses. No causal lift, no image-quality claim, no advertiser-lift claim, no production readiness, and no X revenue figure. Replay and simulation cannot supply that evidence, which is why the ceiling is TEST.

The defect worth knowing. The service used to compare an outcome snapshot's experiment id against itself, so a mismatched experiment passed silently. The fix binds an expected experiment id into the request (service.py:338), and a regression test asserts an unexpected experiment now forces HOLD. A self-comparison always passes and never throws, so only a test that supplies the wrong experiment catches it.
